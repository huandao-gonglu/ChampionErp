## 通用读取机制

普通业务查询在 `business_data_composition.py` 声明资源，绑定原 Store/service、参数、
权限、默认摘要及明细路径。页面与 AI 共用；新增查询资料不再按用户问法新增专用 AI 工具。
首批七类资源是运费规则、运费版本、Yandex 发布仓、核价模板、草稿内容、逐 SKU 核价
明细和商品 SKU 事实。现有 focused 写能力及领域事务保留，不声称已经迁移全部业务入口。

读取支持字段选择、精确筛选、路径展开和分页。摘要不是完整数据的访问上限。
数据读取按紧凑 JSON 的 12,000 字符预算分页；这是单次业务查询预算，不是整轮模型
输入上限，也不等同于脚本输出或框架工具定义的大小。目录只在明确请求时返回参数 Schema。
两个基础读取入口常驻，其余工具由原生 ToolSearch 按需发现，每次最多三个结果。

新核价保存实际包装、候选、排除事实、费率与统一选仓依据；历史没有过程记录时明确
标注缺失，不事后补造。脚本输出的 Python 类型对象通过原生输出 hook 规范化，避免
核价已完成后因消息 JSON 编码失败而中断；未替换原生执行、重试或历史。

## 发布环境真实业务验证

本地协议回归使用受控模型；以下问答通过 `https://hdgl.cc.cd` 的正式业务与对话入口，
使用生产配置的真实模型，并核对原生消息历史和工具返回。

1. **物流限制查询**：读取 22 条 Yandex 规则，与页面接口逐条对照一致。
   AI 正确区分 Extra Small 的 500 g、60/90 cm、1,500 RUB 上限与普通件的“表内未注明”，
   正确说明固定费按包裹收取、按实重计费，以及轻小件货值按最终买家售价校验。
2. **历史报价解释**：选择真实的两规格已保存草稿。AI 读取包装、三个候选、当前仓库
   配置与费率，说明 Extra Small 没有出现在保存的候选中；历史未保存逐渠道原因，
   因此没有将当前配置推断冒充当时的排除回执。
3. **新预览与统一选仓**：对相同草稿只预览、不应用。两个规格均返回三个候选，实际
   排除清单为空；共同仓库合计运费分别为 45.03、50.83、63.09 CNY，统一选择最低方案。
   AI 成功读取新增过程依据并解释其余候选是成本更高，没有被准入规则拒绝。
   模板缺少普通件完整准入资料的限制仍明确保留。

每轮测试前后比较该商品与草稿的原始 JSON 摘要，均一致；未应用售价、发布商品或采购。
验收对话保留在生产账号历史中，临时验证会话已退出。
