# 网页端、桌面端与统一业务后端拆分计划

状态：五步对应的代码拆分、退役入口清理及隔离回归已完成；真实部署切换和现有数据迁移尚未执行，需提供目标环境。本文件记录经审计收紧后的完整五步计划，范围限定为业务拆分，不包含收费、订阅、商业授权、多租户平台或商业发行体系建设。

## 目标与完成标准

网页端和桌面端共用一套 Vue 业务界面、一个业务后端和同一份业务数据。网页端提供可在线完成的功能，桌面端另外提供浏览器、CLI 等本机能力。本机执行代码继续使用 Python，由 Electron 管理独立执行器。

全部拆分完成时，应同时满足：

1. 统一后端在没有用户 Chrome、CLI 和本机目录的服务器上，能够正常启动并处理订单、在线商品等业务。
2. 本机执行器无需初始化 ERP 业务数据库、`AppContext` 或业务后台服务，就能执行浏览器和 CLI 操作。
3. 页面、Agent 工具和既有后台业务均能通过同一边界使用本机能力，结果由后端通过原有业务入口保存。
4. 网页和桌面读取同一份业务数据。桌面关闭后，后端业务继续运行，需要本机执行的操作明确反馈连接不可用。
5. 桌面安装包携带前端和本机执行器，完整本地 ERP 后端的启动、调用与打包路径已经清理。

## 职责边界

| 部分 | 主要职责 | 数据归属 |
| --- | --- | --- |
| 统一业务后端 | 商品、草稿、订单、在线商品、发布、业务校验、素材资产、领域 Job、Agent 与消息历史 | 业务数据库、共享业务配置、店铺 API 凭据、已入库资产 |
| 本机执行器 | Chrome/Edge 启停与连接、页面读取、浏览器 AI、Gemini Canvas、CLI、必要的本机文件读写 | 浏览器资料、CLI 本机配置、代理与路径配置、临时文件 |
| Electron 主进程 | 执行器生命周期、桌面与后端连接、本机调用转发 | 当前桌面连接和进程内调用关联 |
| Vue 界面 | 业务展示、编辑和操作，根据运行环境呈现可用入口 | 页面交互状态和必要的展示缓存 |

本机执行器返回页面事实、文本、结构化结果或文件。业务对象的归一化、合并、版本检查与保存仍由原 Service、Store 负责。

## 实施约束

- 优先移动已有本机代码、抽开实际依赖，避免重写已经工作的浏览器实现或复制两套解析规则。
- 普通本机操作使用请求与响应。既有后台业务继续使用原领域 Job，不给每次调用新增持久任务。
- 通信层只关联调用和结果。业务状态、幂等、保存与实际执行回执由现有 owner 管理。
- 本次连接面向发起操作的桌面实例，不建设设备注册中心、多设备调度或跨设备故障转移。
- 保留现有取消、超时、版本校验及结果待确认语义。传输失败不触发已发送操作的自动重放。
- 参数和返回值在接口边界校验，业务规则在对应领域校验，不在每一层重复同一套检查。
- 新增持久化状态、重试或恢复逻辑前，必须说明当前机制无法覆盖的具体业务场景。没有实际依据就不增加。
- Pydantic AI 继续独占 Agent run、工具循环、审批、Deferred 和消息历史。按工具已有执行语义接入，不把所有本机调用统一改成 Deferred。
- 保留真实持久化数据和外部契约的读取、迁移能力。替换旧路径后清理旧实现及只验证旧行为的测试，不增加双写、隐式回退或长期双轨流程。

## 第一步：拆开采集读取与业务入库

### 改造内容

以“从当前浏览器标签页采集 1688 商品”为第一条链路，拆分现有 `collect_from_browser_tab` 的两组职责。

| 本机操作 | 后端业务 |
| --- | --- |
| 定位用户指定的商品标签页 | 根据业务目标读取已有商品 |
| 读取页面、提取商品事实 | 商品归一化、质量检查与合并 |
| 处理原有登录、验证码等待和页面身份检查 | 素材资产登记、商品与草稿保存 |
| 获取依赖本机登录的详情内容和素材 | 生成业务响应和列表投影 |

具体实施：

1. 抽出不访问业务库的采集读取函数，显式接收浏览器连接、目标页面和本机配置。
2. 定义采集输入与输出数据契约，仅包含现有业务需要的事实、素材和诊断信息。
3. 将页面提取与纯解析逻辑按实际依赖归到本机侧，后端保留商品领域的规范化和保存逻辑。
4. 通过现有采集入口组合两部分，在开发环境验证拆分。
5. 保持当前采集完整性判断、部分结果和错误语义。登录与验证码等待继续属于采集交互。

主要入口：

- [浏览器采集工作流](../erp_web/runtime_units/source_collect_workflows.py)
- [采集业务能力](../erp_web/runtime_units/collect_capabilities.py)
- [浏览器连接服务](../desktop_runtime/browser_debug_service.py)

### 验收标准

- 采集读取函数能够在没有 ERP 业务数据库的环境中返回一件商品的事实资料。
- 商品保存仍调用原 `ProductStore` 入口，采集读取函数没有业务入库副作用。
- 正常采集、等待用户验证及页面离开目标商品的现有行为可通过原入口验证。

## 第二步：抽出执行器并接入 Electron

### 改造内容

1. 新增独立的 `desktop_runtime/` Python 包和启动入口，先迁入浏览器连接基础与第一步的采集读取能力。
2. 执行器只初始化本机配置、浏览器连接和必要临时目录，显式管理自身依赖。
3. Electron 复用现有子进程启停思路，通过进程管道发送固定操作并接收结果。标准输出用于通信，日志单独输出。
4. `preload` 按界面需要暴露明确接口，Electron 主进程校验调用来源与参数。
5. 执行器返回进度、结果或原有错误，Electron 在退出时收尾本次启动的执行器。
6. 网页与桌面共用业务组件，根据桌面能力入口决定本机操作是否可用。

共享数据契约放在不依赖业务上下文的模块中，沿用项目的 Schema 与前端类型生成方式。执行器通过固定业务动作提供能力，不开放任意远程命令或脚本执行接口。

主要入口：

- [Electron 主进程](../front/desktop/main.cjs)
- [preload](../front/desktop/preload.cjs)
- [本机执行器进程管理](../front/desktop/runtime.cjs)
- [独立执行器入口](../desktop_runtime/__main__.py)

### 验收标准

- 桌面能够通过 Electron 调用独立执行器并取得采集资料。
- 执行器导入和启动不拉起业务数据库、`AppContext` 或后台业务服务。
- 普通网页能正常使用已有业务页面，本机操作入口按环境展示。

## 第三步：接通统一后端与桌面本机调用

### 改造内容

复用现有 HTTP 路由体系，实现桌面主动等待本机调用、回传执行结果的简单通道。后端按本次业务调用关联发起操作的桌面连接。

调用内容包含关联标识、操作名和参数，响应包含同一关联标识及结果或错误。关联保存在当前连接的内存中，现有领域 Job 继续持有业务生命周期。

1. 后端采集服务通过该通道调用桌面执行器，继续负责商品校验和保存。
2. Electron 在主进程维持连接并转发调用，执行过程不依赖某个 Vue 页面持续挂载。
3. 本机取得的素材通过后端上传和资产入口交接，保存后的业务数据使用后端资产引用。
4. 两端普通业务请求统一指向同一后端，同时核对 AI 流、文件预览和下载地址。
5. 按实际部署地址调整现有 Host/Origin 配置，继续使用项目已有请求校验边界。
6. 路由留在 `http_route_units/`，编排交给 facade 或 focused service，相关请求契约与 Schema 同步。

完整采集链路：

```text
桌面提交采集请求
  → 后端采集服务调用当前桌面
  → Electron 转发给本机执行器
  → 本机读取商品与必要素材并返回
  → 后端归一化、登记资产、保存商品
  → 网页与桌面读取同一份商品
```

当前桌面连接不可用时，本机调用明确结束并反馈。后端继续按各业务已有规则解释失败或结果待确认，通道不承担自动重放和跨重启恢复。

### 验收标准

- 桌面采集商品后，网页能够查看该商品和图片。
- 关闭桌面后，订单中心与在线商品管理仍由统一后端正常工作。
- 未连接、用户取消、一次传输失败均能正确结束受影响调用，业务结果不会被伪报成功。
- 商品和素材的持久引用不依赖用户电脑上的绝对路径。

**第一批完整交付包含第一至第三步的采集链路，完成第一步本身只代表职责拆开。**

## 第四步：迁移 Browser AI、Canvas、CLI 并覆盖业务入口

### 改造内容

1. 将浏览器 AI、Gemini Canvas 和 CLI 的本机执行部分迁入执行器，复用已建立的连接与进程通信。
2. 后端现有 Browser/CLI 适配器改为调用本机执行器，沿用原有输入、输出和实际支持的能力。
3. 将本机路径、浏览器资料、代理及 CLI 配置留在本机。后端保留业务模型绑定和必要的连接引用。
4. 连接测试和能力探测在对应本机环境执行，探测结果关联实际连接配置，复用已有探测规则。
5. 打通图片往返，后端提供本次源图，本机完成处理并返回结果，现有图片服务校验和保存结果资产。
6. 逐项接通页面操作、Agent 工具和既有后台图片批次，保持来源关联、版本检查和批次结果语义。

API 模型继续使用 `ai_model_factory` 与 `ai_direct_request_service`，Agent 继续由 `AiAgentFactory` 和 Pydantic AI 管理。普通同步工具、持久领域 Job 与 Deferred 各沿用原职责，不新增 Agent 执行或恢复协议。

网页端可使用后端能够独立执行的模型与业务。某项操作绑定本机模型时，页面明确提示使用桌面端；模型选择由用户或既有业务配置决定。

主要入口：

- [Browser Provider](../erp_web/services/ai_gateway_browser_provider.py)
- [浏览器 AI 运行实现](../desktop_runtime/browser_ai_runtime.py)
- [CLI Provider](../erp_web/services/ai_gateway_cli_provider.py)
- [Gemini Canvas](../erp_web/services/gemini_canvas_runtime.py)
- [既有领域 Job 衔接](../erp_web/services/agent_job_service.py)

### 验收标准

- Browser/CLI 通过原业务入口返回可用结果，连接测试在本机执行。
- Canvas 从后端资产取得源图，结果经原图片服务保存，原图和来源关联正确。
- Agent 触发的本机操作返回真实工具结果，历史和审批仍由原生机制维护。
- 后台图片批次可使用发起任务时关联的桌面连接，页面切换不改变执行归属。
- 现有登录等待、取消、超时和结果待确认行为通过迁移后的实际入口验证。

## 第五步：统一启动、迁移数据并清理旧路径

### 改造内容

1. 网页和桌面正式使用同一业务后端地址，统一核对普通 API、AI 流、图片和文件访问。
2. 桌面启动入口只负责前端、本机执行器及连接管理，后端自行管理业务服务和后台任务。
3. 调整构建脚本和安装资源，收集本机执行器实际依赖，清理完整 ERP 后端的冻结与启动路径。
4. 迁移已有业务数据与素材，先备份，再执行一次性迁移并核对业务 ID、关联关系、历史回执和资产引用。
5. 按职责拆分配置，业务配置及后端所需 API 凭据归统一后端，本机环境配置和浏览器资料保留在本机。迁移后的凭据应通过原配置 owner 读写。
6. 清理被替代实现、配置、说明及只验证旧行为的测试，补齐新职责边界的架构守卫。
7. 更新 [AI 上下文地图](ai-context-map.md)、[前端规范](../front/前端规范.md)及[桌面打包说明](desktop-packaging.md)，反映最终入口。

数据库引擎按当前实际业务需要处理，代码拆分继续复用现有 Store 的职责、短事务和版本规则。数据迁移与程序切换单独执行，不采用两份业务库长期双写或相互同步。

### 验收标准

- 安装后的桌面程序能够连接统一后端并使用全部既有桌面业务能力。
- 桌面执行器和打包依赖中没有业务数据库初始化、订单同步或发布 worker 的启动路径。
- 后端无需本机 Chrome、CLI 或浏览器资料即可处理独立在线业务。
- 迁移前后的业务 ID、关联和历史回执一致，图片引用可访问，浏览器登录资料可继续在原电脑使用。
- 第一至第四步链路均通过新启动与打包入口验证。

## 验证与推进顺序

按“采集职责拆分 → Electron 接入 → 两端采集闭环 → 其余本机能力 → 启动打包与旧路径清理”推进。每步交付可验证结果后再扩展范围。

测试围绕实际入口和本次改动选择，复用已有用例与夹具。只为新边界或明确回归缺口增加测试，不为通信实现细节建立大量重复测试。

- 后端涉及导入或模块边界时，完成编译检查与架构测试；后端重构完成后运行 `.venv/bin/python -m pytest tests -q`。
- Electron 按改动运行现有桌面测试，后续命令随入口调整同步更新。
- 前端按影响范围执行测试、类型检查和构建，共享 Schema 变化后生成并检查前端类型。
- 发行入口验证使用不含真实业务凭据的测试数据，不触发真实店铺写入。
