# ERP 个人账号管理实施方案

状态：技术选型与功能范围已确认，尚未实施。本文是后续开发方案；本次交付仅新增方案文档。

## 1. 目标与范围

保留现有 Python 后端、Vue 前端和 Electron 本机执行器，在 ERP 内加入个人账号管理，开放用户自行注册。网页与桌面连接同一业务后端，使用同一套账号；不同用户的业务数据相互隔离。

账号功能的实施范围包括：

- 用户注册、登录、退出、查看当前账号、修改密码。
- 管理员查看用户、创建普通用户、启用或禁用普通用户、重置普通用户密码。
- 个人业务数据、文件、后台任务与桌面连接的归属和隔离。
- 将现有业务数据归属初始管理员，完成网页、桌面和服务端的切换验证。

本次范围不包含充值、支付、会员套餐、自动续费、企业组织、团队协作、细粒度权限编辑器、第三方登录和独立身份服务。后续收费面向个人，支付直接接官方渠道；本次只提供稳定的用户 ID，不提前增加余额、套餐或会员占位字段。

## 2. 已确定的技术选型

| 部分 | 方案 |
| --- | --- |
| 后端 | 沿用现有 Python HTTP 路由、facade、service 与 Store 分层 |
| 前端 | 沿用 Vue 3、Pinia、Vue Router、Axios 及现有 AI 流传输 |
| 账号与会话存储 | SQLite，独立的账号数据库 |
| 密码哈希 | 新增直接依赖 `argon2-cffi`，使用其 `PasswordHasher`，不自行实现哈希算法 |
| 登录状态 | 服务端随机会话，浏览器通过 HttpOnly Cookie 携带 |
| 桌面登录 | Electron 主进程管理远端会话，沿用固定后端代理及本机调用通道 |

账号业务参考 `hdgl_toekn` 的功能划分。其 Go、Gin、PostgreSQL、Redis、JWT 与刷新令牌流程不复制到 ERP。现有 Python 技术栈足以完成本次需求，不另引入 Web 框架、Redis 或微服务。

实施时确认并固定 `argon2-cffi` 版本，同步依赖和第三方声明。其传递依赖由包管理工具安装，不成为桌面执行器依赖。

## 3. 账号与会话

### 3.1 用户

用户最小字段为：稳定的 `id`、登录邮箱、显示名称、密码哈希、角色、状态、业务空间标识及创建/更新时间。邮箱去除首尾空白并统一大小写后判重；业务关联使用用户 ID，不依赖邮箱或显示名称。

- 角色固定为 `admin`、`user`；自行注册只创建 `user`。
- 状态固定为启用、禁用。首版通过禁用停止账号访问，保留业务数据。
- 初始管理员由部署命令创建，密码通过交互输入。初始化完成后开放注册，不采用“首位公开注册者成为管理员”。
- 首版管理界面只管理普通用户，管理员修改自己的密码走个人账号入口；不建设角色配置系统。
- 注册邮箱用于登录，本次不接邮件验证和邮件找回，不将邮箱标记为已验证。忘记密码由管理员重置。

密码策略集中定义：允许密码管理器和粘贴，最少 15 个字符、最多 128 个字符，不强制字符种类组合或周期改密。验证、哈希和参数更新使用密码库提供的能力。

### 3.2 会话

账号库保存会话与用户的关联、随机凭据的哈希、CSRF token、创建时间和过期时间。原始会话凭据只交给客户端，不写入数据库明文、日志或 URL。

- 浏览器 Cookie 使用 `HttpOnly`、`SameSite=Lax`、`Path=/`；公网 HTTPS 环境使用 `Secure`。
- 首版会话有效期统一为 7 天，到期重新登录，不增加 JWT、Refresh Token 或多套续期机制。
- 退出撤销当前会话；修改密码、管理员重置密码或禁用账号时，撤销该用户的全部会话。
- 受保护请求检查会话有效性和用户状态。登录后的写请求统一校验会话绑定的 CSRF token。
- 注册、登录沿用 JSON 请求契约和来源校验，并做基础的账号/IP 时间窗口限流。规则集中实现，不增加验证码、风控平台或永久封禁流程。

账号数据库只持有用户与会话事实，不保存商品、店铺授权、模型工具计划或领域任务状态。

## 4. 个人数据与运行时边界

### 4.1 按用户选择业务空间

采用“共享账号库，每位用户独立业务数据目录”的方式，复用现有 `AppPaths`、`AppContext` 和各领域 Store。目录布局为：

```text
<ERP_APP_DIR>/
  accounts.sqlite3          # 所有用户的账号与会话
  erp.sqlite3              # 已有业务库，绑定初始管理员
  config/                  # 已有个人配置
  data/                    # 已有业务素材、辅助库和历史
  users/<user_id>/
    erp.sqlite3            # 新用户的业务库
    config/
    data/
```

业务空间标识由服务端分配并保存在账号库中。现有目录作为初始管理员的空间保留；新注册用户使用自己的目录，只初始化公开默认配置，不复制管理员的商品、凭据、对话和个人设置。

个人范围包括商品、草稿、订单、在线商品、店铺授权、个人 API 密钥、模型配置、Agent 记忆、消息历史、素材和领域任务。代码资源、公开类目资料及默认模板可以共享。

部署级平台应用凭据继续由服务端持有。实施时检查 `.env` 和模型工厂的环境变量读取，区分平台应用凭据与已有个人 API 密钥，避免新账号隐式继承原用户密钥。本次不提供平台统一的付费 AI 额度。

### 4.2 请求、后台执行与文件

1. HTTP 公共入口先认证，从服务端会话取得用户，再选择其业务上下文，随后进入原路由和业务服务。
2. 请求体、查询参数中的 `user_id`、业务 ID、文件路径或桌面连接 ID，都不能替代登录身份选择业务空间。
3. 使用请求局部上下文及显式依赖传递用户归属，不通过切换进程全局 `_context` 服务并发用户。线程、线程池、异步任务和既有领域 Job 必须延续原所属空间。
4. 继续使用单个业务后端进程。上下文和已有 worker 由统一生命周期管理，按实际业务需要装配；不为每次请求或每个注册账号提前启动整套后台服务。
5. 重启恢复、取消、幂等、版本校验和结果待确认仍由原领域服务负责。退出登录不等于取消已提交的业务任务；账号操作不新增任务撤销或重放协议。
6. 图片、文件、导出、AI 流、工具结果与普通 API 使用同一归属边界。文件访问只允许当前用户的业务目录，不能因知道绝对路径而跨用户读取。

个人隔离覆盖完整业务链路后，才开放多个账号使用；不能以“登录页面已完成”代替隔离交付。

### 4.3 现有职责保持清楚

- 账号 Store 管理用户与会话；`ProductStore` 继续管理商品和草稿；`ConfigStore` 继续管理当前业务空间的配置与凭据。不增加通用 Store 代理层。
- Pydantic AI 继续负责 Agent run、工具循环、审批、Deferred 和消息历史。账号模块只提供可信归属，不重写 Agent 执行机制，也不把账号管理能力加入模型工具清单。
- 管理员拥有账号管理入口，不默认增加浏览其他用户商品、对话或店铺凭据的界面。

## 5. HTTP、网页与桌面接入

### 5.1 接口与页面

新增独立的账号路由单元、facade、service、Store 和 Schema。请求字段通过 `validate_request_payload(..., endpoint=handler.path)` 校验，与 `REQUEST_CONTRACTS` 同步；响应沿用项目现有风格。

| 接口 | 用途 | 访问范围 |
| --- | --- | --- |
| `POST /api/account/register` | 自行注册普通用户 | 公开 |
| `POST /api/account/login` | 登录并建立会话 | 公开 |
| `GET /api/account/session` | 返回当前用户和 CSRF token；未登录返回空用户 | 公开查询当前会话 |
| `POST /api/account/logout` | 撤销当前会话 | 已登录 |
| `POST /api/account/password` | 验证原密码并修改密码 | 已登录 |
| `GET /api/admin/users` | 分页查询用户 | 管理员 |
| `POST /api/admin/users` | 创建普通用户 | 管理员 |
| `POST /api/admin/users/status` | 启用或禁用普通用户 | 管理员 |
| `POST /api/admin/users/password` | 重置普通用户密码 | 管理员 |

Vue 增加登录、注册、个人账号和用户管理页面。用户管理入口仅向管理员显示，后端仍独立检查角色。原 `components/auth/` 继续表示店铺和服务授权，账号页面与 API 使用独立命名。

前端只保存当前用户、CSRF token 与展示状态，不向 `localStorage` 或 `sessionStorage` 写会话凭据。Axios 与 AI 流请求统一携带登录态和必要的 CSRF 信息；未登录返回 `401`，权限不足返回 `403`。

退出或切换账号时清除业务 Store、聊天订阅和页面缓存，再加载新账号数据；主题、语言等设备偏好可以保留。

### 5.2 公开资源与平台回调

登录、注册页面和必要静态资源公开，业务 API 与业务文件统一鉴权。`Host/Origin` 校验继续保留，与身份认证各司其职。

平台订单通知、OAuth 回调继续使用现有 token/state 验证。生成回调时附带可定位用户空间的归属信息，接收端定位空间后验证其原有凭据；归属信息本身不作为登录凭据。已配置的旧回调归初始管理员，保留原凭据校验能力。公开例外按具体端点声明，不整体放开 `/api` 或 `/auth` 前缀。

### 5.3 Electron

- 应用先展示登录页面；登录成功后，主进程为该用户建立本机调用连接。
- Electron 主进程接收并持有远端会话，通过固定后端代理统一携带。渲染页面只取得用户信息和 CSRF token，不直接读取会话凭据，也不直接接收上游 HTTPS 的 Secure Cookie。
- 首版远端会话仅保存在主进程内存，退出桌面程序后重新登录，不另做本机密码保存或凭据保险库。
- 后端核对当前会话与桌面连接归属。登录退出、账号切换或会话失效时，断开对应本机调用连接；已发送操作继续按原有结果待确认规则处理，不自动重放。
- 浏览器资料、CLI 配置仍在当前电脑。ERP 登录不替代外部平台登录，不迁移或同步浏览器资料，不扩展设备注册和调度平台。

## 6. 现有数据与部署切换

实施时先备份当前业务数据库、配置和素材，再创建初始管理员，将现有业务目录绑定给该管理员。此步骤不修改已有商品 ID、对话 ID 或任务关联，也不复制出第二套继续写入的旧业务库。

新用户从空业务空间开始。初始化命令可再次执行检查状态，但不能重新分配已有归属、覆盖账号或重置密码。迁移核对以实际切换时的快照为准，沿用 [服务器部署记录](server-deployment.md) 的备份和发布方式。

公网访问在账号和隔离验收完成后切换：由 HTTPS 入口转发到现有回环后端，设置实际 `ERP_PUBLIC_URL`，验证网页 Cookie、桌面代理及平台回调。无域名时核实 IP 证书与自动续期配置，不要求用户电脑逐台配置 SSH。方案文档本身不执行服务器切换。

## 7. 实施顺序与完成标准

按以下顺序形成可验证结果，不将中间状态视为完整交付：

1. **账号基础**：实现账号 Store、密码哈希、会话、初始化管理员及注册/登录接口，完成真实 HTTP 认证测试。
2. **用户归属**：接入个人业务空间、文件与后台执行归属、平台回调，完成两个用户的并发隔离测试。
3. **界面与桌面**：接通注册、登录、个人账号、管理员页面及 Electron 登录后连接，验证退出和切换账号。
4. **迁移与发布**：核对原数据归属、构建网页和桌面程序、执行回归，再完成目标环境部署与 HTTPS 验收。

验收必须覆盖：

- 自行注册只能成为普通用户；重复邮箱、错误密码、禁用账号、过期会话有稳定结果。
- 普通用户不能调用管理员接口。退出、改密、重置密码和禁用后，原会话按约定失效。
- 用户 A 不能通过用户 B 的商品、任务、会话、文件或桌面连接标识读取或操作 B 的数据；后台任务与重启恢复也保持归属。
- 网页与桌面使用同一账号时读取相同数据；切换账号后不显示前一账号的业务缓存。
- 已有商品、草稿、历史、凭据和素材保持完整，新账号为空；平台回调仍定位正确用户并验证凭据。
- Pydantic AI、原业务审批与任务取消语义保持，原有业务功能通过回归。

后端完成编译检查、架构测试及 `.venv/bin/python -m pytest tests -q`；前端运行相关测试、类型检查及构建；桌面运行 Node 测试并验证安装包登录链路。删除仅验证“业务接口匿名可用”等退役行为的测试，保留并适配仍有业务价值的用例，不为旧测试保留匿名旁路。

实施完成后更新 [AI 上下文地图](ai-context-map.md)、[前端规范](../front/前端规范.md)、[桌面打包说明](desktop-packaging.md)及部署记录。当前文档交付只需检查方案与链接，不运行无关功能测试。

## 8. 后续充值与会员的衔接

未来充值订单、消费流水与会员权益关联稳定用户 ID。官方支付回调处理交易确认，账号会话负责用户身份，两者保持各自职责。

支付产品开通、套餐定价、消费规则及手动续费/自动续费，在该功能启动时另行确定。本次不接支付 SDK、不生成支付订单、不为会员功能增加 feature flag 或备用实现。

参考：[argon2-cffi 官方文档](https://argon2-cffi.readthedocs.io/en/stable/)、[OWASP 身份认证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[OWASP 会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。具体字段、依赖版本与请求契约在实施后以代码为准。
