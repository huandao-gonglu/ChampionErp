# SKU 选品、核价与发布

商品保存实际存在的 SKU。各平台草稿引用这些 SKU，分别选择发布范围、填写销售资料和应用售价；平台发布适配器负责把同一套管理模型转换为各平台请求。

## 页面操作

1. 商品库 → 编辑 → **规格与 SKU**：维护名称、规格属性、采购成本、供应商库存、图片、条码、包装长宽高、重量及电池/液体属性。支持勾选多个 SKU 后批量填入明确相同的资料，再统一保存。包装单位统一为 cm、kg；采购成本为 CNY。
2. 草稿箱 → 编辑 → **SKU**：新草稿默认选中全部启用规格，停用规格不选中；可用表头父复选框全选/取消全选，部分勾选时显示半选状态。保存后的手动选品保持不变，新增启用规格默认勾选。填写平台卖家编码和可售库存，选择组合展示或独立刊登。新增 SKU 或库存为空时，可售库存默认填入该 SKU 的供应商库存；已填写的数量（包括 0）保留，后续供应商库存变化不会覆盖。供应商库存缺失时仍需手动填写。空白卖家编码在保存时生成。展开详情查看商品来源资料；修改成本、包装或条码时点击“去商品编辑”，定位对应 SKU。草稿只选择销售图片、设置费用/售价和平台差异属性。
3. **核价**：进入后读取已选 SKU 的成本和包装，点击“计算核价”才开始试算。顶部可修改核价范围、直接编辑汇率；手动汇率逐项标记，刷新 API 参考时保留覆盖，可恢复实时值。左侧维护固定费用、各市场费用、定价规则和国际运费偏好，可保存、编辑或设置默认模板；模板默认不保存手动汇率，不保存商品资料、官方佣金、自动运费和单个 SKU 覆盖。右侧按 SKU 合并采购与包装、按市场列出运费、官方佣金、售价和 CNY 利润；完整列表连续滚动，无分页，支持搜索及市场/异常筛选。明细抽屉展示物流原币、计费重量、官方佣金依据和成本拆分，可仅覆盖当前 SKU 的运费或售价。缺少成本/包装时进入商品补充；保存后刷新商品资料并保留未保存的草稿文字和费用。修改参数后须手动重新计算；计算中、失败或参数变化时旧结果停用，全部选中项就绪后才能应用。预览不保存草稿；成功预览在服务端保留十分钟；应用售价时检查参数和配置仍一致，直接保存本次 SKU 选择、费用和已核验价格，不再请求物流和佣金。平台仓库与渠道沿用当前真实配置，不使用原型中的示例仓库。
4. **类目/属性 → 发布预检**：共同属性填写在草稿，颜色、尺寸等差异属性填写在 SKU 对应目标市场下。SKU → **属性 / 详情** 按当前类目显示真实字段，枚举字段可搜索平台值，数值字段沿用单位控件；无需手填属性编号。AI 属性填写从主对话发起，明确公共或 SKU 范围及目标市场；页面保留手工编辑并同步实际保存结果。预检核对每个 SKU 的必填资料、售价和组合约束；发布摘要列出每个规格的价格及库存。
5. 发布后回到 **SKU** 查看各目标的远端身份、结果与错误。确认创建成功的相同内容会跳过；失败项可重试。结果未知的项必须先对账，不会再次创建。

## 数据归属

| 对象 | 保存内容 |
| --- | --- |
| `product.sku_items` | 稳定本地 ID、来源 SKU ID、商品事实、启用状态及最新来源快照 |
| `product.source.skus` | 采集边界的来源规格数据，用于核对来源 |
| `draft.sku_items` | `sku_id` 引用、选中状态、卖家编码、可售库存、销售图片选择、目标差异属性、逐目标核价和远端结果 |
| `draft.pricing` | 共用费用及目标定价规则；不作为所有 SKU 的统一售价 |
| `draft.grouping` | 用户选择的组合/独立刊登方式和平台组名 |

Ozon“Объединить на одной карточке”和 Yandex 分组属性 200 由系统按刊登设置派生，
不进入公共属性或 SKU 属性的 AI 待填列表。属性页显示“刊登分组（系统填写）”，
组合展示时显示当前平台组名；组名为空时沿用商品标题。
独立刊登时省略可选分组字段；平台要求必填时，以每个 SKU 的卖家编码生成稳定且不同的分组值。
公共属性或 SKU 属性中残留的旧组名不能覆盖当前刊登方式。可编辑属性不保存第二份组名；
预检与发布即时使用相同规则，修改组名或切换刊登方式后无需重新调用 AI。

同一 URL 再采集复用商品及 SKU 身份；不同 URL 不继承最近商品。来源变更会更新未被人工编辑的事实，已编辑事实保留，新的来源值仍写入快照。来源删除的 SKU 停用并保留关联；人工新增规格保留原启用状态。成功采集替换来源属性快照，避免旧噪声残留；人工属性与平台属性分别保存。

SKU 按供应商提供的实际组合保存，不做颜色 × 尺寸的笛卡尔积扩展。已有商品资料且没有变体的商品也有一个 SKU；空白采集结果不会生成无名称的单规格占位记录。复制草稿重新生成卖家编码、清空远端关联，保留已应用的逐 SKU 核价；发布预检仍检查报价是否有效。停用商品 SKU 后，引用它的草稿必须重新选品。

草稿根级不再保存实物 `brand`、`model`、`stock`、`sku`、`upc`、`package_dimensions` 或 `publication`。销售库存和编码位于 `draft.sku_items[]`；条码、包装、成本和运输属性直接读取商品 SKU；远端事实位于 SKU 的 `publications[target]`。平台适配器的单规格视图仅在内存中派生，不能写回草稿。旧草稿读取时去掉这些废弃副本，保存接口拒绝重新写入，不改变已有 SKU 库存、核价和发布记录。

`draft_read.pricing_summary` 按目标返回所选 SKU 的编码、售价、币种及应用状态，不以共用模板价格判断 SKU 是否已核价。库存修改统一使用 `draft_changes_apply` 并指定 SKU。UPC 分配给指定商品中缺条码的启用 SKU 各领取一个唯一号码，可用 `sku_ids` 限定范围；保留已有条码，号码不足时整批回滚。前端分配前保存当前商品编辑。

## SKU 图片

- 采集既下载商品展示图，也下载全部 SKU 原图。公共图不再截断前五张，同一来源图片只入池一次；原图地址保留在来源记录和素材 `raw.source_url`。
- 商品 `sku_items[].image_asset_id` 指定默认图；草稿 `sku_items[].overrides.image_asset_id` 指定该草稿用图。没有覆盖时继承商品默认图，显式空值使用公共发布图片。
- SKU 详情提供带缩略图的图片池选择器，可选原图、上传图和处理后的图片。图片页显示每张图用于哪些 SKU，展开“关联 SKU”选择后通过现有保存入口自动保存。
- 规格图仅作为对应 SKU 的发布主图；不会自动把所有颜色图片混入公共图集。下载路径、分发域名变化不会改变资产身份。
- 显式“替换所选图片”会更新当前草稿引用，不修改商品默认图。单独换图不使已应用的核价失效。
- 关联图片被删除时，预检返回 `image_asset_id` 问题并保留受影响的 SKU 名称和卖家编码，引导重新选图；仍会报告其它 SKU 的问题。

## 平台组织方式

| 平台 | 当前实现与校验 |
| --- | --- |
| Mercado Libre | 每个 SKU 转为一个单品请求。组合内独立定价要求店铺启用 User Products，使用共同 `family_name` 并核对类目的变体属性和父级共同属性。传统模型的多 SKU 组合会被拦截，可明确选择独立刊登。各 SKU 保存自己的全局/站点身份及异步任务。 |
| Ozon | 每个 SKU 使用自己的 `offer_id`、价格和包装资料导入。组合名称写入当前类目提供的“Объединить на одной карточке”属性，变体属性按类目定义校验；没有组合能力或不能区分规格时拦截。导入成功与最终卡片合并是两个状态，未取得远端组合身份时显示“组合结果待确认”。 |
| Yandex | 每个 SKU 使用自己的 offer 身份，组合通过类目属性 200 以及 distinctive 属性描述。共同属性必须一致。原生发布流程继续推进各 SKU 的映射、价格、库存与确认阶段，确认响应中的 `groupId` 用于核对分组。 |

组合校验失败不会自动改为独立刊登。即使单品全部成功，只要没有足够的远端分组证据，也不会标记“已确认组合”。平台最终展示仍需平台返回结果，本次开发没有调用真实刊登接口。

## 执行与持久化

核价预览与应用售价都将已选 SKU 一次提交后端。同一批共享店铺配置、汇率、费率版本及 Ozon 可用仓库/配送渠道；每个 SKU 按自身成本、包装和覆盖值独立报价。公共查询失败时，本批后续规格直接显示相同错误，不重复等待接口；下次核价重新查询。界面显示等待时间，操作日志记录批次号、总耗时与 Ozon 共用渠道查询耗时；后端 `erp.pricing` 日志另有逐批进度和 SKU 失败原因。等待期间修改 SKU、市场或核价参数后，旧结果不能应用。

三种定价方式与手动计算操作不变。明确的费用规则按固定、比例、保底和封顶区间直接求解，并检查费用舍入后最低可用分价；最终用实际发布售价和该价的官方费用严格核验目标利润率或成本加价目标。手动售价只计算实际利润，不为达标而改价。规则缺失、跨档或费用变化时仍按候选售价批量补查；无法取得达标且有官方依据的报价时禁止应用。Yandex 使用当前 Campaign 的官方费用试算；Ozon 当前覆盖中国／香港卖家的 rFBS 基础佣金；Mercado CBT 按销售国家、物流方式和刊登类型读取官方网页费率及标准低价固定收费。Mercado 阿根廷完整收费规则、哥伦比亚低价商品豁免等未确认范围明确返回错误。官方资料更新后，下次核价重新获取；历史手填佣金报价保留查看，但不能直接用于发布。盈亏平衡价按本次有效费率估算，最终收费仍以平台实际服务、下单日规则及适用协议为准。

SKU 属性统一由主对话完成。按目标用 `draft_attributes_read(scope=sku)` 读取全部已选启用 SKU 的有效事实，需要时分页，再查询全部平台属性定义和必要的枚举候选。主对话根据事实填写，通过 `draft_sku_attributes_update` 保存指定 SKU 的差异属性；公共字段通过 `product_attributes_update` 保存。前端保留手工编辑并展示主对话的实际保存结果。

后端属性写工具只校验当前类目、字段作用域、值类型/数量/单位和真实枚举 ID，不调用模型。网络查询后在商品锁内重读，仅合并本次字段，保留其他 SKU、目标和商品原始资料。类目切换后拒绝旧类目写入。写入成功不代表全部属性完成，主对话需核对全部定义与实际已存值，报告未填及缺资料项。

品牌优先使用平台实际提供的无品牌候选，只有非常确定目标品牌时才使用具体品牌。不从混合 SKU、模糊营销描述或图片比例推断精确参数。资料不足时在主对话询问用户。旧页面批量推进、专用填写及复核模型均已下线，Pydantic AI 继续拥有主对话的工具循环与消息历史。

## Demo 数据与验证

商品 schema 为 4。现有商品、草稿及发布身份继续保留。已持久化的 SKU `image` 地址在读取边界迁移为 `image_asset_id`，新写入只保存资产引用；不支持旧的按下标选品格式。

已采集商品缺少 SKU 本地图片时，运行 `.venv/bin/python scripts/repair_sku_image_assets.py --draft-id <草稿编号>` 预览，追加 `--apply` 备份数据库后下载并保存；备份和核验报告保存在 `data/audits/sku-image-repair/`。该操作保留草稿选品、核价与发布记录。

实际 URL 采集样本为 `https://detail.1688.com/offer/527745534623.html`：15 个 SKU、28 项商品属性。S/M/L/XL 的包装重量分别为 4.5/8/9.5/16.5 kg，保留实际的 15 个组合。浏览器验证了选中 2 项、保存后刷新，仍保留完整 15 项及选品范围。核价验证使用测试物流参数，不代表真实物流商报价。

业务回归覆盖来源身份和人工编辑保留、草稿隔离、逐 SKU 成本/包装、组合属性约束、部分失败重试、未知结果防重发、异步任务恢复与旧页面保存。架构测试约束三平台统一使用 SKU 组入口。临时验证截图和接口响应转储保存在仓库外的系统临时目录，任务结束后清理。

预检区分“全部差异属性为空”和“已填但组合重复”，显示真实类目字段与重复 SKU 名称。不会提示在没有颜色字段的类目里填写颜色，也不会为了通过预检编造不同数值。枚举比较使用平台值 ID，不以展示文本或集合顺序制造差异。

Mercado User Products 的自定义规格使用 `sku_items[].custom_attributes_by_target[target]`，每项为 `name` / `value`。SKU 属性编辑区允许增删改；投影为 `sku_custom_attributes` 后，编译器按 `name` + `values[].name` 发送，不能伪造类目字段 ID。自定义名称不能与现有类目 ID/名称重复，组合内使用同一组自定义名称，真实值组合必须唯一。自定义规格不免除类目必填要求，传统刊登模式继续明确拒绝此能力。

### 预检问题汇总

各平台按错误类型、字段、原因、级别及处理建议汇总同类问题，受影响的规格保存在 `affected_skus`（`sku_id`、`sku`、`name`）中，前端可展开查看。`field` 保留相对 SKU 的字段路径，`message` 只描述问题，不拼接 SKU 名称。整组组合校验使用明确的错误码。只有“所有差异属性为空”与同一批 SKU 的必填差异属性缺失同时出现时，才将组合校验作为主问题的 `related_issues` 关联说明，不重复计数；规则身份与处理建议仍完整保留。不同属性、受影响 SKU 范围、其他组合错误和处理建议不会因此合并。已填值但规格组合重复时仍独立阻断，补齐属性后必须重新预检；列出的可选差异字段无需全部填写。错误和提醒数量直接取当前展示的问题条数，市场范围内去重，市场之间分别计数。发布校验与预览保留同一份 SKU 明细和关联说明，是否阻断发布的规则不变。属性标签及填写位置取当前类目定义：差异属性引导到 SKU → 属性 / 详情，共同属性继续在类目属性页处理。

### 核价缓存与应用耗时验证（2026-10-20）

使用现有 9 个 SKU 和店铺配置的隔离数据副本，经真实 HTTP 核价入口调用 Yandex 接口；应用只写副本，现有草稿未改变。按外部请求审计中的实际发送记录计数：

| 操作 | 费用请求 | 仓库请求 | HTTP 总耗时 |
| --- | ---: | ---: | ---: |
| 首次计算（无规则缓存） | 2 | 1 | 8.84 秒 |
| 重复计算（复用规则，批量核验） | 1 | 1 | 4.90 秒 |
| 应用已核验预览 | 0 | 0 | 0.81 秒 |

应用结果与预览逐项一致。上述为本次实测，远端接口响应时间会波动；收费规则变化或跨价格档位时可能需要额外核验。佣金规则缓存一小时，成功预览有效期十分钟；参数、商品资料、店铺或物流配置改变会阻止应用旧预览，须手动重新计算。


### 求解器与取整校验验证（2026-10-21）

新增逐分枚举对照覆盖固定费、比例费、保底、封顶、物流最低货值、档位边界和接近零的净收益斜率。真实业务样本仍使用上述 9 个 SKU 的隔离副本，经 HTTP 入口和真实 Yandex 接口验证；应用只写副本，原草稿内容未变。

| 操作 | 费用请求 | 仓库请求 | 汇率请求 | HTTP 总耗时 | 本地规则求解总耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首次计算 | 2 | 1 | 1 | 12.37 秒 | 1.10 毫秒 |
| 重复计算 | 1 | 1 | 0 | 4.29 秒 | 0.82 毫秒 |

## 来源资料变更与迁移

商品 SKU 是成本、包装、条码、规格、供应商库存和电池/液体属性的唯一可编辑事实源。商品根级保存实物品牌、型号、材质及包装内容；平台属性保留枚举映射与本地化表达。修改商品事实后，受影响草稿的报价应用状态和预检失效，相关平台属性标记待复核；历史报价依据、发布回执和订单快照不重写。

Schema 5 保留 Schema 4 读取迁移。`scripts/migrate_product_source_facts.py` 默认仅预览，`--apply` 在完整数据库备份后事务迁移：商品非空值优先，商品空值仅接收所有草稿一致的值，冲突草稿副本直接删除。旧商品级采购成本移至 `source.legacy_product_cost_cny` 作为待确认参考，不能自动套给每个 SKU；可在商品编辑器确认适用范围后批量填写。重复迁移不再修改数据。

AI 使用 `product_read` 获取商品版本和 SKU，再用 `product_sku_facts_update` 局部批量写入；草稿保存及核价入口拒绝来源字段覆盖。`draft_changes_apply` 仅负责平台属性和销售库存。
