# SKU 选品、核价与发布

商品保存实际存在的 SKU。各平台草稿引用这些 SKU，分别选择发布范围、填写销售资料和应用售价；平台发布适配器负责把同一套管理模型转换为各平台请求。

## 页面操作

1. 商品库 → 编辑 → **规格与 SKU**：维护名称、规格属性、采购成本、供应商库存、图片、条码、包装长宽高和重量。包装单位统一为 cm、kg；采购成本为 CNY。供应商库存仅供采购参考，不自动当成平台可售库存。
2. 草稿箱 → 编辑 → **SKU**：勾选需要刊登的规格，填写平台卖家编码和可售库存，选择组合展示或独立刊登。空白卖家编码在保存时生成。展开详情可覆盖成本、包装、图片、条码、固定费用、目标物流报价及手动售价，填写平台差异属性。覆盖只影响当前草稿。
3. **核价**：设置共用费用和目标市场规则。系统按每个已选 SKU 的实际采购成本、包装资料及覆盖参数独立计算。预览只更新编辑器；应用售价才保存。修改成本、包装或费用后需重新核价；发布前也会核对计算依据，避免使用旧报价。
4. **类目/属性 → 发布预检**：共同属性填写在草稿，颜色、尺寸等差异属性填写在 SKU 对应目标市场下。目前差异属性编辑使用平台属性编号。预检核对每个 SKU 的必填资料、售价和组合约束；发布摘要列出每个规格的价格及库存。
5. 发布后回到 **SKU** 查看各目标的远端身份、结果与错误。确认创建成功的相同内容会跳过；失败项可重试。结果未知的项必须先对账，不会再次创建。

## 数据归属

| 对象 | 保存内容 |
| --- | --- |
| `product.sku_items` | 稳定本地 ID、来源 SKU ID、商品事实、启用状态及最新来源快照 |
| `product.source.skus` | 采集边界的来源规格数据，用于核对来源 |
| `draft.sku_items` | `sku_id` 引用、选中状态、卖家编码、可售库存、草稿覆盖、目标差异属性、逐目标核价和远端结果 |
| `draft.pricing` | 共用费用及目标定价规则；不作为所有 SKU 的统一售价 |
| `draft.grouping` | 用户选择的组合/独立刊登方式和平台组名 |

同一 URL 再采集复用商品及 SKU 身份；不同 URL 不继承最近商品。来源变更会更新未被人工编辑的事实，已编辑事实保留，新的来源值仍写入快照。来源删除的 SKU 停用并保留关联；人工新增规格保留原启用状态。成功采集替换来源属性快照，避免旧噪声残留；人工属性与平台属性分别保存。

SKU 按供应商提供的实际组合保存，不做颜色 × 尺寸的笛卡尔积扩展。没有变体的商品也有一个 SKU。复制草稿重新生成卖家编码、清空核价和远端关联；停用商品 SKU 后，引用它的草稿必须重新选品。

## 平台组织方式

| 平台 | 当前实现与校验 |
| --- | --- |
| Mercado Libre | 每个 SKU 转为一个单品请求。组合内独立定价要求店铺启用 User Products，使用共同 `family_name` 并核对类目的变体属性和父级共同属性。传统模型的多 SKU 组合会被拦截，可明确选择独立刊登。各 SKU 保存自己的全局/站点身份及异步任务。 |
| Ozon | 每个 SKU 使用自己的 `offer_id`、价格和包装资料导入。组合名称写入当前类目提供的“Объединить на одной карточке”属性，变体属性按类目定义校验；没有组合能力或不能区分规格时拦截。导入成功与最终卡片合并是两个状态，未取得远端组合身份时显示“组合结果待确认”。 |
| Yandex | 每个 SKU 使用自己的 offer 身份，组合通过类目属性 200 以及 distinctive 属性描述。共同属性必须一致。原生发布流程继续推进各 SKU 的映射、价格、库存与确认阶段，确认响应中的 `groupId` 用于核对分组。 |

组合校验失败不会自动改为独立刊登。即使单品全部成功，只要没有足够的远端分组证据，也不会标记“已确认组合”。平台最终展示仍需平台返回结果，本次开发没有调用真实刊登接口。

## 执行与持久化

`sku_model.py` 拥有规格规范化和引用契约；`sku_publish_projection.py` 创建临时单品输入；`sku_publish_adapter.py` 是发布注册表入口，原生平台适配器仅处理单品 I/O。ERP SKU 发布编排不参与 AI Agent 生命周期。

发布清单冻结每项身份及内容指纹。请求发送前持久化 `dispatching`，响应按 SKU × 目标立即保存。重试会读取最新远端事实，复用既有身份，跳过已经成功且内容未变的项。未知结果保留任务身份，已有任务可继续只读确认。没有任务身份的未知结果需要人工核对。

普通商品/草稿保存不能覆盖远端事实，也不能删除已发送的 SKU 行或更换其卖家编码；数据库在事务中合并最新远端状态，防止旧页面保存抹除后台结果。

## Demo 数据与验证

商品 schema 为 4。按用户授权，本次清理了历史商品、平台草稿、图片关联及发布记录，保留店铺授权、配置和 UPC 池，不增加历史 SKU 格式兼容或迁移代码。

实际 URL 采集样本为 `https://detail.1688.com/offer/527745534623.html`：15 个 SKU、28 项商品属性。S/M/L/XL 的包装重量分别为 4.5/8/9.5/16.5 kg，保留实际的 15 个组合。浏览器验证了选中 2 项、保存后刷新，仍保留完整 15 项及选品范围。核价验证使用测试物流参数，不代表真实物流商报价。

业务回归覆盖来源身份和人工编辑保留、草稿隔离、逐 SKU 成本/包装、组合属性约束、部分失败重试、未知结果防重发、异步任务恢复与旧页面保存。架构测试约束三平台统一使用 SKU 组入口。验证产物位于本地 `data/audits/sku-workflow/`，不包含在产品源码中。
