## 实测中发现并处理的问题

- 初始页面同源脚本递归展开了历史业务记录，超出配置验收目标；中止该只读扫描并撤销
  会话，改为配置全量对照、其他读取有界样本，不把未完成扫描算作通过。
- 初次结构化答案数值虽一致，但仓库题额外读取历史草稿/报价。补充配置取数说明，
  并将无请求的历史扫描加入失败条件；不能只用工具成功或答案字段正确来判断效率。
- 一道题的“实际核价路线”可能指历史用过的路线，也可能指当前配置候选，原断言却
  只接受后者。保留歧义试跑与失败回执，将题意和字段明确为“当前配置中可参与比价的
  全部发布仓”，同版单独复验。最终六项由五个同版成功样本及该项澄清复验组成，
  没有把历史用过的两个仓误判为当前全部配置的三个仓。

对比基准为 1.2.59 的最终线上样本，三道题文本相同，每版各一次。峰值下降约
**14%–19%**；这不是稳定性能保证。外层调用包含脚本，脚本内业务调用单独留存，
不能把一个脚本等同于只读取一次数据。累计输入包含多轮及可能的缓存输入，不等于
唯一数据量或实际费用；新增结构化题与自然语言题不混作同题基准。

主执行说明字符数从 **7,589 降到 3,433**，是其中一个来源的减少，并非整个上下文
减少同样比例。发布环境规则分项为：

| 来源 | 字符数 |
|---|---:|
| execution | 3,433 |
| business | 1,853 |
| system | 4,450 |
| user | 0 |
| response | 1,093 |

这些来源合并后还包含原生动态说明；最终有效 instructions 约 13,641 字符。

业务工具目录。规则/工具字符、历史各类消息字符与上游实际 token 分开记录，不虚构
上游没有提供的分项计费 token。用户偏好与完整原生历史没有被裁剪或覆盖。
