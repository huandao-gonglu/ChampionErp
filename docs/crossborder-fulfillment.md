# 跨境巴士履约

本阶段在现有授权配置、订单中心和订单详情中完成履约，不新增首次接入流程或独立日志页面。

## 产品入口

- 授权配置 → 跨境巴士 → 账号授权：企业 `client_secret` 获取/刷新 Token；跨境巴士账号密码换取用户授权记录 `app_uid`。密码只用于当次请求，不落库，密钥与 Token 不返回前端。
- 同模块 → 默认履约：维护物流收货地址及支持的物流商；不再展示默认方案配置卡片、重复合作仓列表或方案编辑弹窗。
- 已保存的履约规则和后端匹配、自动预报行为保留；本次移除配置界面不清除持久化规则或已创建报单。
- 订单中心 → 详情 → 跨境履约：查看详情、录入/管理包裹、获取/更新面单、报单前覆盖方案、立即提交、状态同步、取消和异常详情。列表只保留“详情”入口，分别展示平台状态和 ERP 处理进度；采购登记、国内单号、面单、预报等事实在详情中核对。

Yandex FBS 在「商品与采购」先确定采购收货仓、收件人、电话和完整地址，再下单。报单沿用该仓库，只选择基础服务和附加服务。官方交货地址及原有备注保留为参考，不再要求货代收货地址与官方交货点相同。
合作仓 API 当前只返回 Yandex 平台及仓库，没有 CEL／GUOO／UNI 及具体运输服务的兼容字段。收货仓界面从本单平台 IMPORT 交货点名称识别并显示跨境物流商，例如 CEL、GUOO(GTA)、UNI，同时保留原名称作为识别依据。`YANDEX_MARKET` 是配送合作模式，`Самовывоз` 是自提方式，不能代表跨境承运商；交货点未知、缺失或承运商冲突时显示“待确认”。GUOO(GTA) 与 GBS(GUOO) 分开展示，不合并为同一承运商。
「平台授权 → 跨境巴士 → 默认履约 → 物流设置」以跨境巴士授权身份和合作仓 ID 为范围，每仓可维护多个具名收货地址、备注、启停及默认优先级。每个地址可勾选多个支持的运输服务（平台物流商）：CEL、UNI、GBS(GUOO)、GUOO(GTA)、Ural、ATC。枚举只用于设置地址的支持范围，不提供 Express、Economy 或交货节点范围配置。账号授权和地址配置统一在平台授权的跨境巴士设置中维护。 新增或编辑地址时，可粘贴收件人、电话和完整地址，点击「解析并填入地址」复用采购地址解析器；优先提取明确标注的收货联系人和电话，同类多个号码取优先级最高的首个，手机和座机分别填入，忽略多余资料，缺失字段提示补全，核对后再保存。

采购弹窗只选择配置好的具体收货地址，由服务端读取订单平台物流商并筛选；采购请求不得传入物流商或运输方式来覆盖平台订单。尚未识别平台物流商时需先同步平台交货信息，不允许手动选物流商绕过筛选。默认地址只提高排序，不自动选择。保存绑定地址 ID、版本及规则快照。旧地址资料继续可读，旧规则仅保留已确认的平台与物流商，旧运输方式及节点限制不再参与匹配；已采购的原始快照继续保留。
选仓界面不读取或展示基础/附加服务及费用，服务留在跨境报单环节选择。2026-10-10 实际读取当前账号的三个 Yandex 合作仓：开放 API 合作列表原始回执仅有平台、仓库 ID、名称和编号，服务回执仅有基础/附加服务的 ID、名称、金额；没有余额、官网业务范围或完整收货地址。这不代表官网没有这些信息，官网余额的数据源及登录方式需单独核实，不从截图填入固定余额。
采购预览绑定本单收货仓版本及地址快照；1688 创建前再次核对。采购提交中、结果未知或回填待完成时禁止重新绑定；配置未变的有效采购仍锁定仓库和地址。物流设置保存新版本后，引用旧配置的订单统一标为绑定失效，已有采购也必须重新确认；允许仓库与实际地址同时变更。已有采购重绑须核对包裹收货安排，原采购记录的地址快照保持不变，重绑不代表已发包裹自动改寄。旧采购可以先登记事实，报单前必须人工确认实际寄往的仓库和地址；不把旧地址对应关系自动升级为承接能力。
其他平台保留按授权店铺、履约模型、配送来源等条件匹配的默认方案，已有配置继续可读。平台仓履约订单不进入此链路。

## 展示边界

- 平台状态按统一状态显示；Yandex 备货、打包、已备妥作为平台附注，不与采购登记、跨境仓进度混用。
- ERP 处理进度使用实际采购数量及本地仓库回执：待采购登记 / 采购登记中 → 待报单 → 已创建预报 → 待到仓 / 包裹已入库 / 已打包 → 仓库已发货。取消、未知创建结果和错误单独提示；错误不覆盖最近确认的仓库进度。
- 单包裹和多包裹统一：采购完成且查询到国内运单，或已经人工录入国内包裹，尚未报单时显示“待报单”；直接录入无需先完成采购登记。国内物流状态保留在提示和包裹详情中，不覆盖 ERP 步骤与异常。“待报单”不等于可立即提交，包裹分配、数量、面单和服务方案仍须通过校验。
- 报单阻断先指出有效采购超量和采购同步记录的分配冲突，再检查包裹完整性。提示包含销售 SKU、相关采购单及数量；区分“已有运单但分配未齐全”“尚未取得国内运单”和“实际采购数量不足”，不把分配冲突描述为等待发货。作废记录不参与校验。
- 国内单号和国际面单可分别补齐，没有单号只显示“未录入”，不推测供应商未发货；已录入单号不等于已到仓，已保存面单不等于已发货。
- Yandex 包裹商品图与订单列表、详情共用已同步的 Yandex 在线商品图片，按 business、campaign 和远端 SKU 精确关联。图片只接受 HTTPS 地址；未同步或缺图时不混用本地发布图或采购图，也不把 ERP `/file` 地址交给仓库。该读取不触发平台同步或已创建报单的远端更新。创建或更新包裹时，平台原图经默认 S3 托管原样交付，核验内容哈希和带跨站 Referer 的公开读取，避免源站防盗链造成仓库破图；托管失败阻止该次写入。源图下载复用安全传输，代理 Fake-IP 或私网解析必须先修正网络配置，不能绕过校验。
- 仓库已发货是 V1 的终点。页面不展示尚未接通的国际运输、妥投、签收或履约“已完成”。平台已发货但没有跨境预报时明确显示“无跨境预报”，不能认定这条 ERP 履约链路已经完成。
- 列表批量读取脱敏履约摘要，不创建履约记录，也不发起远端请求；详情与列表共用进度展示规则。

- 更换某个 SKU 的采购时，先作废该 SKU 的原采购记录，再直接录入新包裹或登记新采购。作废与移除该记录的包裹分配在同一事务内完成，同采购单和同运单的其他 SKU、未关联该采购的直接包裹保留。报单已开始或结果待核实时禁止作废；两个有效国内运单共同交付时须确认合单服务。

## 首条链路

1. 完成平台授权，并在订单中心同步待发货订单。
2. 在现有授权模块授权跨境巴士。在「物流设置」为合作仓配置地址及已确认承接规则，再在「商品与采购」选择匹配的具体收货地址；无需先配置全局默认方案。
3. 确认采购来源，1688 采购直接使用该仓的收货地址；人工采购登记须核对实际收货安排。进入跨境履约后沿用采购仓，基础服务选择一项，附加服务按需多选。
4. 获取平台生成的国际面单及对应面单号，并录入国内包裹。目的国为可选资料，缺失时不阻止预报，也不猜测；已有目的国不可覆盖。
5. Yandex 单箱待发货订单支持“获取平台面单”；默认自动预报开启且方案、包裹齐备时后台自动获取。读取平台 PDF 和箱号后托管，成功后保存对应面单资料。其他平台或平台不提供箱号时，可人工粘贴公开 HTTPS 地址或上传不超过 8 MB 的 PDF。上传复用现有默认 S3 托管，在独立对象路径保存，并以匿名下载校验内容一致；不使用本机地址作为仓库面单地址。
6. 包裹可直接关联销售商品，或关联有效采购记录，填写物流单号和数量；物流公司选填，未知时留空，不影响保存或报单。无需采购单号也可直接录入，不要求整单没有采购记录；某 SKU 原采购作废后可直接补录新包裹。直接包裹不生成虚假采购记录。逐 SKU 的有效采购数量与直接包裹数量之和不得超过销售数量；提交前必须覆盖全部销售数量，并为每条有效采购分配齐全包裹。
7. 默认自动预报开启时资料齐备后自动创建正式预报；关闭时点击“立即提交”。创建前重新读取所选合作仓库的服务，校验基础服务恰好一项及附加服务仍可用，不假设服务编号。没有自动规则时保存本单方案不会直接预报，点击“立即提交”后发送。
8. 进入订单详情的“跨境履约”页签时，对已关联或创建待确认的本单自动查询一次；停留期间不轮询，后续点击“同步”或“核实创建/取消结果”查询。同步直接返回本次结果；失败保留最近确认进度，不后台重试。已确认跨境巴士发货后，ERP **履约状态**更新为已发货；平台订单状态仍由平台订单同步负责。

本版先补齐资料再创建正式单，避免将缺少面单或商品数量的正式单送入仓库。创建后仍可更新面单和完整国内包裹列表，打包后锁定资料。
报单备注在本单「设置报单方案」中选填，默认空白，随方案保存并在履约页回显。只有用户填写的内容才作为创建接口 `introduce` 发送；留空时省略，不自动填入平台、订单号或地址备注。备注只属于本单，不随收货仓资料复用；编辑复用现有租约和版本校验，预报开始或结果未知后锁定，不通过本地修改假装已更新远端备注。历史记录没有该字段时按空值读取，不改写已创建远端订单。

Yandex 新报单使用真实平台订单号作为 `order_number`，面单箱条码仍独立保存在 `sheet_order_sn`。创建成功后执行一次官方[关联平台订单](https://kuajing84.apifox.cn/480099010e0.md)，由跨境巴士匹配其已同步的店铺订单；创建接口不接受店铺、账号、平台状态及订单时间字段，不通过备注拼接这些信息，也不推算超时取消时间。关联前核实远端 ID、待打包状态、仓库、渠道及本地账号和版本。历史已创建报单保留原预报号，避免破坏原单的查询、更新和取消；未发送的旧记录在首次创建前采用真实平台订单号。

关联状态与仓库履约进度分别保存。明确失败后可在履约页点击「关联平台订单」重试；结果未知或进程中断时禁止重放，需在跨境巴士核实。关联失败不重复创建报单、不自动重试，也不覆盖已确认的仓库进度。关联成功回执仅确认接口受理成功；官方查询接口未提供该栏全部字段，店铺、物流、平台状态、下单及截止时间的最终显示需在跨境巴士查看。未查询到关联订单时应核对平台订单号和跨境巴士的店铺订单同步，不能认定整栏已补齐。
面单读取不自动修改平台分箱、不改变平台发货状态。Yandex 需具备订单处理权限，且已在平台生成单箱面单；多箱订单不能把多张面单压成一个箱号，暂停自动获取并要求人工处理。Market Yandex Go 不支持箱号数据接口时使用人工补充。当前 Ozon、Mercado Libre 尚未接入自动获取，页面明确显示人工补充提示。

Yandex 官方接口：[订单面单 PDF](https://yandex.ru/dev/market/partner-api/doc/ru/reference/order-labels/generateOrderLabels)、[箱号数据](https://yandex.ru/dev/market/partner-api/doc/ru/reference/order-labels/getOrderLabelsData)。直接调用固定面单路径，不依赖即将退役的回执 `url` 字段；采用平台返回的 `fulfilmentId` 箱条码，不把 `orderNum` 当面单号。

获取失败保存独立 `label_error`，在面单区域显示原因，页面读取到新错误时弹出提示；不自动重试，用户点击“重新获取面单”重试。旧 `label_next_attempt` 数据可读但不再触发任务。重新获取失败保留原面单，不覆盖仓库状态错误。获取与预报共用占位；重复点击、期间取消、资料版本变化及授权切换均不得写入过期结果。

S3 上传前 `HeadObject` 返回 404 表示对象尚不存在；SDK 保留原始回执，统一请求管理不为它创建拒绝记录或增加连续失败计数。上传与对象校验、公开读取使用同一操作范围，正常的不存在查询不能阻止上传后再次校验。其它请求的 404、S3 的 403 等仍按错误处理。交付错误明确显示托管配置、S3 上传/对象校验或公开下载阶段，并保留已脱敏的权限、DNS、网络原因。

## 协议和状态

官方文档：[跨境巴士 API](https://kuajing84.apifox.cn/)。服务端只使用官方生产域名 `https://api.service.kuajing84.com`。

合作仓库实际回执中的 `section_id` 和仓库 `id` 可能是字符串，服务费用 `gold` 也可能是字符串。
在协议边界统一转换为数字，再供默认方案、仓库选择及后端承接校验使用；已保存的合作仓库缓存读取时做相同归一化。
页面直接展示已读取的合作仓库，不以默认方案数量或平台订单配送来源数量判断合作仓库是否为空。
收货地址选择及本单服务配置每次打开均刷新合作仓库；官方列表没有收件地址，实际收货资料在物流设置中维护。不得直接比较 Yandex 与跨境巴士的仓库 ID。物流设置通过 `GET /api/logistics/settings` 读取、`POST /api/logistics/refresh` 同步合作仓、`POST /api/logistics/address` 保存地址。编辑支持将同一地址记录改到另一已合作仓并修改收件资料，使用版本校验；启用且匹配平台物流商的地址才进入候选。配置版本变化、停用或原配置不存在都会使引用它的旧绑定失效，采购与报单校验不再豁免已采购订单。历史无配置 ID 的绑定保留读取，但报单前须重新选择受管理的地址。

订单「商品与采购」以及绑定失效时的「跨境履约」提供「重新设置报单绑定」，展示旧绑定和最新候选。保存须再次核对订单、地址版本及已有采购确认；确认后推进本单收货仓版本，旧报单服务方案不再有效，必须按新绑定重新选择服务。手动提交、重试、自动报单以及创建占位均验证配置有效性，不能只靠前端禁用。配置保存与创建占位共用短事务：配置先变则旧绑定不能领取创建占位；创建已占位或结果未知时暂不允许修改其引用的配置。已创建远端报单保持原仓库、单号及查询／取消链路，不通过改配置或重新确认覆盖远端单据。
取消履约只结束当前报单，不使有效收货绑定失效，也不解除已采购订单的换仓限制。待发货订单直接使用「设置报单方案」选择本次服务，不需要单独点击重新安排或再次确认未变化的收货仓。保存新方案时，存在原远端 ID 的先只读查询该 ID 并确认作废；再通过 `FulfillmentStore.change` 在同一个短事务中复核履约版本、订单状态、账号、采购占位及收货绑定，调用 `archive_cancelled` 归档原报单并保存新方案。任一校验或写入失败都保留旧报单，网络查询不持有事务锁。创建时保存收货快照用于历史归档；没有快照的旧数据只在绑定版本和仓库仍匹配旧方案时采用现有绑定，不能把新仓库记到旧单。

收货绑定、采购历史、国内运单、面单和备注保留，保存方案不递增收货绑定版本；保存后须显式提交才能解除 `awaiting_resubmission`，已有自动规则不能直接重报。只有引用的仓库、地址或承接配置失效时才需先重新确认绑定；该保存不归档或重启履约，不再依赖 `fulfillment_revision`（旧请求字段仍可读取）。历史取消标记 `confirmation_required` 不再独立使绑定失效，实际配置校验仍照常执行。创建未知、取消待确认和有效占位继续禁止重报。

重报保留真实平台订单号及远端重复校验，不自动添加后缀或关闭防重；远端若仍拒绝同号创建则展示原回执，保持人工核实，禁止循环重试。创建未知结果查询排除已归档远端 ID；已知当前 ID 的状态、包裹及平台关联查询只接受该 ID，不能把旧作废单绑定回来。创建回执若返回归档 ID 同样保留未知结果。国内包裹更新按照[官方接口](https://kuajing84.apifox.cn/439191672e0.md)使用当前 `order_id`。

官方 [创建订单 OpenAPI](https://kuajing84.apifox.cn/439191670e0.md) 中 `OrderDataItem.country` 不在 required 中，未提供时省略。服务按[合作服务接口](https://kuajing84.apifox.cn/462942497e0.md)读取；结合官网录单的基础服务单选交互，`core_data` 作为单选组，`optional_data` 作为附加多选组。

本地包裹分配按销售 SKU 保存，`purchase_record_id` 为空表示直接录入，非空时继续验证有效采购记录及数量。发送 `package_list` 前按国内运单去除首尾空白、统一大小写后分组，每个实际运单只发送一条包裹。`num` 是该包裹的商品总件数，不是包裹数。同一采购单拆成不同运单仍为多个包裹；多个采购单或直接商品分配共用一个运单只为一个包裹，不能按 SKU 行数或采购单号数量判断合单。多运单仍须显式确认已选择的仓库合单服务，`add_service` 按用户方案发送，不因分组合并而自动修改服务或费用。

管理包裹弹窗与履约详情同样按规范化运单号去重展示：同单号一张包裹卡片，快递公司和单号统一编辑，卡片内保留每条商品的数量及采购关联，可添加或移除商品。修改单号与其他包裹相同时合并展示，未填写单号的新包裹各自保留。删除包裹移除该运单全部商品分配，移除商品只影响该条明细；保存仍提交完整的逐商品分配，不丢弃或重复累计数量。同运单存在不同快递公司时须人工核对，可选择统一公司或明确清空为未填写。`DomesticParcel.carrier` 省略或空白均保存为空字符串，保留已有公司名称，不根据单号猜测。

新增商品以销售数量减去当前全部包裹分配计算可用数量，不使用采购剩余数量，也不回退到已分配齐全的首个 SKU。商品已分配齐全也不能禁用录入包裹：此时打开补发编辑区，选择漏发商品及原运单、填写补发单号和数量，公司选填。确认后从原包裹移动对应数量到补发运单，保留原包裹其余商品；移空的包裹移除。部分漏发拆分明细，整个 SKU 漏发移动整条明细，总销售数量不增加。已有采购关联随商品保留，不要求新采购单、不作废原采购；无采购商品同样支持补发。补发草稿可取消，确认前不改变包裹，最终沿用完整包裹保存及多运单合单流程。商品选择只列销售商品，不再把同一 SKU 按直接录入与采购记录重复列出；未分配商品按已有有效采购的可用数量保留内部来源。打开弹窗不对已有包裹分配的 SKU 再追加采购明细；其他商品的物流候选带入同样受销售数量上限约束。保存前的超量提示列出对应运单及件数，保留输入供核对，不静默删除或缩减已保存明细。普通业务校验只展示原错误，只有真正的履约版本冲突才刷新版本并提示复核。

同运单多条商品的验货说明逐条保留 SKU、标题、规格、数量、采购平台及采购单号。接口 `img` 只接受单张图片，以首张非空商品原图为包裹主图，其余商品原图链接保留在验货说明中；Yandex 所有原图先完成既有托管与访问验证再分组，任一图片交付失败仍阻止报单。单值 `from_order` 只在来源平台及采购单号一致时发送；混合采购单不拼造单号，真实来源保留在各商品说明。`from_platform` 在平台一致时保留。此逻辑用于新创建和以后显式触发的包裹更新，不迁移、不自动修正已报单据。

2026-10-15 核对官方创建及更新包裹 OpenAPI：`package_of=1` 表示国内快递单号，采购平台 `from_platform`、采购单号 `from_order` 均不在 required 中。直接包裹省略这两个来源字段，验货说明只使用真实销售商品信息；与采购包裹共用运单时逐商品保留已有采购来源，聚合包裹省略不一致的单值来源字段。直接录入沿用收货仓、服务、面单、自动/手动报单及未知结果处理，不新增独立报单流程。

收货仓保存与采购数量占位共用订单数据库的短事务；版本、账号、平台物流方案及已采购状态均在事务中复核。报单保存及提交校验收货仓版本，平台物流方案变动需重新确认承接范围，但不自动变更已经采购的仓库。官方交货地址变化不改变收货点匹配；平台物流商缺失或变化时须同步核对。旧官方交货地址映射停止使用，已有远端预报继续按原仓和原单号查询、更新。

## 并发、核实和取消

- `(platform, account_id, platform_order_id)` 在 SQLite 中唯一；Yandex 新预报使用真实平台订单号，其他平台及历史已创建报单保留原稳定预报号，原有平台订单身份保持不变。
- 写请求不隐式重试。创建前原子占位，写前标记结果未知；超时或进程退出后保留待核实状态，进入履约页或点击核实才查询，不能再创建一张单。
- 查询接口按预报号前缀检索，必须读完分页并精确匹配 `sheet_info.section_order`；还要核对渠道和仓库，不能拿第一条结果当本单。
- 查询不到不等于未创建，仍保留“创建待确认”；需要人工联系跨境巴士核实，不能点击普通重新提交绕过。
- 所有人工修改携带 `revision`。版本冲突不覆盖新数据；包裹弹窗保留输入，刷新版本后要求人工复核。
- 修改本单方案时暂停自动预报，编辑租约 5 分钟，打开的弹窗每分钟续期。保存/取消恢复预报，关闭浏览器后租约会失效。
- 平台取消和人工取消都优先停止创建；若创建可能已经发送，先核实创建结果再取消远端单。
- 取消发送前持久化占位，超时后等待页面核实，不自动再次取消。收到成功请求回执也要由下一次页面查询确认仓库状态。
- 仓库已发货时保留已发货，并持续显示取消冲突。已入库包裹需人工与仓库处理。
- 账号切换后禁止对旧授权下的履约单继续写入。
- 所有远端请求复用统一外部请求管理；资料更新或授权请求结果未知时，需先按现有请求管理流程核实和解除阻断，不绕过管理器重放。

## 开发入口

- `schemas/fulfillment.py`：配送、配置、面单、包裹、命令和详情契约。
- `stores/fulfillment_store.py`：与订单库共用 SQLite，保存配置、账号凭据、规则、操作占位和履约事实。
- `services/crossborderbus_client.py`：官方协议、Token 刷新、授权、查询分页和安全错误映射。
- `services/fulfillment_service.py`：确定性履约编排、校验、后台业务写入，以及页面请求内的单轮只读状态核实。后台不执行周期状态查询或未知结果核实；业务写入的前置状态检查失败后停下，等待用户处理。
- `services/platform_label_service.py`：复用现有店铺授权读取平台 PDF 与箱条码，核对订单及单箱约束。
- `services/fulfillment_label_service.py`：PDF 交付和公开内容核验，复用唯一 S3 SDK 边界。
- `services/fulfillment_image_service.py`：下载平台原图、复用 S3 内容寻址托管并核验跨站读取；仅在报单写入前运行，图片准备期间取消或版本变化会停止报单。
- `facades/fulfillment_facade.py`：按当前平台账号范围装配；`AppContext` 持有服务并负责关闭。
- `http_route_units/fulfillment_routes.py`：薄 HTTP 适配；全部写请求经过公开请求契约校验。

GET：`/api/crossborderbus/settings`、`/api/crossborderbus/services`、`/api/orders/fulfillment`。
POST：`/api/crossborderbus/{authorize,catalog,save-rule,delete-rule}`；`/api/orders/fulfillment/{fetch-label,upload-label,label,parcels,plan,pause,resume,submit,sync,retry,cancel,associate}`。
这些接口在能力治理清单中登记为可信界面入口，不向模型开放代报、代采购或代取消，不新增 Agent 生命周期。

单次同步是一次业务查询过程：状态接口加待打包时的包裹列表查询（列表可能分页）；Token 过期时还需刷新。因此“一次同步”不保证只有一个 HTTP 请求。未关联且没有创建待确认事实的订单只读本地，不搜索认领远端单、不创建预报、不发送取消或资料更新。页面每 5 秒读取本地快照，展示已提交业务的进度与面单错误；该读取不触发外部查询。方案编辑租约仍每 60 秒续期，仅操作本地数据。

## 验证边界

后端使用隔离 SQLite 和模拟远端回执测试幂等、重启核实、完整数量、兼容范围、账号隔离、入库/打包/发货和取消冲突；前端用组件测试验证实际表单操作、版本冲突、仓库服务切换和遮罩手势。

真实跨境巴士授权、合作仓是否承接具体平台配送方式、资金扣费和生产仓发货仍需用真实账号及测试订单验收；不能把模拟回执测试视为生产履约已完成。


## 同一订单的多 SKU 批量采购

在商品与采购页先确定收货仓，再点击「1688 批量采购」。勾选已确认来源的商品行并核对数量，预览按 1688 返回的供应商交易分组展示商品、运费和总金额；所有分组沿用本单收货仓。核对后一次确认，逐组创建订单；支付宝与先采后付分别检查免密签约，创建后按冻结金额和所选渠道发起支付，结果待核验则暂停后续组。支付宝免密直接扣款，确认区展示其扣款合计；先采后付使用额度。

创建成功的采购单号回填到组内每个商品行。某组失败不撤销其他成功组，可选择剩余商品重新预览；回执未知的组只能查询原请求，不能重新创建。关闭后可重开批量采购查看持久化结果和继续核验，未提交的预览需要重新生成。

卖家发货后刷新采购进度，系统根据交易子项、SKU 和包裹内数量回填国内运单。一个包裹包含多个 SKU 时，各商品关联相同运单并各自保留数量；拆包发货保存多条包裹。无法证明对应关系时要求人工分配，不能把所有运单分配给所有商品。跨境报单继续沿用采购仓库并选择该仓服务。
