# 架构审查参考

仅在进行架构审查时按需使用；本文件不要求每次开发任务执行完整审查，也不授权修改代码或数据。项目硬约束见 [AGENTS.md](../AGENTS.md)，当前入口见 [AI 上下文地图](ai-context-map.md)。

根据真实业务目标、产品阶段、调用方、数据与协议约束评价方案，区分已验证事实、假设和未知项。缺少会改变决策的信息时提出具体问题；其余部分可以继续分析。

审查重点：

- 职责、事实源、依赖方向和信任边界是否清楚，是否存在重复实现、循环依赖或跨层泄漏。
- 抽象解决了什么真实变化，成本由谁承担；既不预设增加抽象，也不预设减少代码就是改进。
- 权限、并发、部分失败、未知副作用、恢复和数据迁移是否符合当前业务契约。
- 方案是否有更小的可行替代，包括保持现状；用与当前决策相关的场景比较，不规定方案或场景数量。
- 改造能否通过真实业务切片验证；阶段划分、共存及回退方式取决于风险和真实兼容需求，避免为假想未来维护第二套系统。

输出结论、证据、实际影响、建议与未决问题。涉及迁移时补充范围、验证方式和退出条件；内容深度与改动风险相称，不套用固定栏目或评分。
