# 草稿属性限制与发布前校验

类目属性从官方接口读取，经 Provider 归一化后由 Catalog 提供给编辑器、Agent 和发布服务。
Yandex 官方接口 [类目属性定义](https://yandex.ru/dev/market/partner-api/doc/ru/reference/content/getCategoryContentParameters)
提供文本长度、数值范围及枚举规则；实际限制按返回的属性定义使用，不为未声明限制的字段套用 100 或 2000 字符。

公共摘要以 `max_length`、`min_value`、`max_value` 显式传递填写所需规则，缺失为 null；数值边界
保留十进制原文。内部定义及已有缓存保持原格式，完整平台绑定不进入公共摘要。编辑界面及 Agent
从同一摘要取得规则。草稿属性列表按游标读完，不能把第一批 100 项当作完整类目。

`schemas/category_constraints.py` 统一检查单值、带单位值、集合和枚举自定义值。Yandex 草稿预检、
发布编译、Agent 属性写入与在线修改调用相同纯规则，保留各自的权限、枚举、单位和作用域校验。
界面按 Unicode 字符计数，显示长度及上下限；输入和已保存值不截断，允许保存未完成草稿，发布前必须修正。
前端数值提示不代替后端 Decimal 校验。平台后续审核仍可能返回接口没有声明的限制。

## 故障样本与证据边界

2026-10-28 只读核对商品 `83cc129afa912596`，其 Yandex 草稿为 `d2f049dd4d5f2`，类目为 `70063695`。
2026-10-26 23:00:54 的发布预览已包含 74 个版本属性，其中 10 个超过 100 字符，草稿预检记录为通过。
保存的版本值使用 `{"values":[{"value":"…"}]}`。2026-10-28 的类目缓存表明 `23476910 / Версия`
是允许自定义值的枚举，`max_length=100`。这份缓存晚于发布，不能冒充当时的原始接口响应。

旧发布编译器对普通文本及标量形式的开放枚举调用长度检查，但对 `values` 数组形式的开放枚举
直接生成提交行。用该草稿实际值和已取得的规则可复现绕过路径；本次把检查移到输入形式分支之前。
此前在线修改还误读 `maxLength/minValue/maxValue`，与内部 snake_case 规则不一致；原测试夹具
同样使用了错误键，掩盖该问题。本次修正夹具，并使用真实规范规则贯穿验证。

原发布任务还有 HTTP 500 / 写入结果未知记录。这与属性长度漏检是两个问题；本次不重放发布、
不修改商品或草稿数据、不把规则修复等同于线上警告已经消失。
