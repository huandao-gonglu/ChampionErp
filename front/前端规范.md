# 前端规范

本文件只记录 `front/` 的开发约定。全项目约束见 [AGENTS.md](../AGENTS.md)；业务契约按需查阅 [AI 上下文地图](../docs/ai-context-map.md)。

## 技术与职责

前端使用 Vue 3 SFC / `<script setup lang="ts">`、TypeScript、Vite、Pinia、Vue Router和 Tailwind CSS。依赖及版本以 [package.json](package.json) 和锁文件为准，使用 pnpm。

- 页面负责组合业务组件；共享状态按业务域放入 Pinia，局部编辑状态留在组件或 composable。
- 普通业务 HTTP 通过 `src/api/client.ts` 的 Axios 实例及 `src/api/` 领域封装调用。该实例发送固定中文语言头并处理时区、presentation header 和错误归一化；成功响应由业务 API 解析。
- AI 对话及展示流使用现有 AI SDK transport，见 [AI Work 契约](../docs/aiworkpage.md)。不要从聊天文字或工具卡反解析业务结果。
- 后端共享契约通过 `scripts/generate_frontend_types.py` 生成 `workflow.generated.ts`，不手工修改生成文件；前端展示类型保留在 `src/types/`。
- 路由标题使用 `meta.title`、说明使用 `meta.description`；界面文案统一使用中文，不提供界面语言设置。
- 样式沿用 `src/style.css` 和 Tailwind 主题，支持现有 `html.dark` 暗色模式；共享组件优先复用，弹窗手势遵守根目录约定。
- 工作台页面标题统一复用 `components/layout/PageHeader.vue` 的紧凑布局，标题和说明在左、操作在右，不再增加品牌眉题或独立标题卡片。
- 任务详情与订单详情统一复用 `WorkspaceDialog` 的右侧 `drawer`。关闭任务详情同步移除地址中的 `task_id`，保留队列来源筛选。
- 不直接渲染未经处理的用户输入 HTML。需要富文本时明确清理边界；项目当前没有 DOMPurify 依赖，不能假定已经存在全局 HTML 清理器。

前端包括个人账号、ERP 工作台和 AI Work。`views/account/`、`api/accounts.ts` 和 `stores/account.ts` 负责注册、登录、个人账号及普通用户管理；`components/auth/` 继续用于店铺和服务授权。当前没有支付、订阅、access/refresh token 刷新或 `{code,message,data}` 自动解包协议。

- 路由加载业务页前查询 `/api/account/session`；普通用户不能进入管理页面，后端独立校验权限。账号界面使用中文文案。
- Cookie 由浏览器或 Electron 主进程持有，Vue 只保存内存用户状态和 CSRF。Axios 与 AI 流通过 `accountTransport.ts` 附加 CSRF，不把会话凭据写入浏览器存储。
- 退出、改密和会话失效通过整页重载释放 Pinia、KeepAlive、订阅和页面缓存，不向已提交任务发送取消。多标签页通过 BroadcastChannel 及聚焦会话核对同步。
- 采集队列、聊天选择和图片请求的存储键通过 `businessStorageKey` 按用户 ID 区分；业务 Store 创建时固定自己的键，避免旧回执写入新账号。设备主题保留。

## 工作区响应式布局

- ERP 工作区主设计视口为 1920 × 960 CSS px，同时覆盖 1440 × 900、1366 × 768 与 2560 × 1440。尺寸以网页内容区计。字体、控件、图标和行高沿用固定尺寸，主区随可用空间伸展。
- 工作区导航展开为 208 px、收起为 64 px，主区两侧内距各 20 px。小于 768 px 时使用顶部工作区选择器。页面级操作放在 `PageHeader` 右侧，空间不足时允许换行，搜索和表单字段限制最大宽度。
- 采集页在视口宽度达到 1280 px 时将打开的详情嵌在列表右侧。两区间距 16 px，详情随可用宽度在 360–440 px 内变化，列表使用剩余空间。勾选、方式、状态、添加时间和操作列使用固定列宽，商品名及 URL 列伸缩，窄窗口可横向滚动表格。
- 小于 1280 px 时，详情在原区域替换列表，由页头返回。返回保留搜索、状态筛选、排序、勾选、浏览条目、滚动位置和焦点。列表按完整筛选结果计算计数和批量范围。存在勾选时，页头批量操作只作用于当前筛选结果中的勾选项。
- 采集页面按可用高度铺开，页头留在滚动区外，列表和详情各自滚动。低于 560 px 的短窗口使用自然文档滚动，页头在顶部吸附。亮暗主题共用布局，选中状态和主操作使用绿色。

## 运行与构建

在仓库根目录使用 `scripts/dev.sh` 同时启动业务后端、Vite 和开发桌面。网页与桌面共用 Vite 热更新，按 Ctrl+C 统一退出。单独操作前端时在 `front/` 执行：

```bash
pnpm dev
pnpm build
pnpm test:run
pnpm typecheck
pnpm types:check
pnpm lint:check
```

`pnpm lint` 会自动修改文件；覆盖率报告用 `pnpm test:coverage`。旧规范的 80% 覆盖率目标是否继续适用尚未确认，当前 Vitest 配置未设强制阈值。

- Web 构建输出到 `erp_web/static/dist`，由 Python `erp_web.server` 托管。
- Vite 默认端口为 3000；代理目标依次取 `VITE_DEV_PROXY_TARGET`、`ERP_PORT`，未设置时为 `http://127.0.0.1:5050`。代理路径以 [vite.config.ts](vite.config.ts) 为准。
- 已启动后端时，`pnpm desktop:dev` 启动 Vite 和开发桌面。`desktop/development.cjs` 管理开发 Electron 子进程，网页经 Vite 同源 POST 和父子进程 IPC 交接到该进程；关闭开发窗口后，网页可重新启动它。开发链路使用 `champion-erp-dev` 并校验实际后端地址，正式版继续注册 `champion-erp`。开发窗口名称带“开发版”，配置和登录资料位于 `champion-erp-front`。页面资源经桌面代理转发给 Vite，业务请求仍经主进程原有会话和连接校验。改动主进程或 Python 代码后重启开发脚本。
- 桌面版使用 Electron；`pnpm build:desktop` 输出到 `front/dist-desktop`。`pnpm desktop:dist` 先构建独立 Python 本机执行器，再生成前端和安装包；不打包或启动完整业务后端。
- 网页和桌面连接同一业务后端。Electron 在主进程代理 API、AI 流、图片及文件，并维持本机调用连接，Vue 页面切换不改变已发起任务的归属。
- `utils/desktop.ts` 的 `hasLocalOperations()` 识别桌面外壳。`desktopOperationReason()` 判断桌面连接，共用模型动作通过 `modelOperationReason(useCase)` 读取配置限制。网页保留本机入口，通过 `vDesktop` 或 `handoffModelOperation` 接管需要桌面的点击，直接唤起客户端。`desktop_use_cases` 由服务端按实际绑定计算，配置错误继续原地显示。提交仍由后端复核。
- `utils/desktopHandoff.ts` 保存短期交接状态，`DesktopHandoffNotice` 负责等待、重试、下载安装和登录后接收。工作台、模型设置和对话分别恢复各自内容，全部完成后才回传打开确认。协议链接只含一次性编号及站点，页面数据经认证 API 交接，凭据不进入协议链接。新增本机入口需复用该流程。
- 采集页提供浏览器采集和 API 采集。两种方式添加链接时都支持粘贴商品链接或完整的 1688 分享文案，分享短链会先转换成标准商品链接再加入列表。开始采集后，浏览器模式交接桌面，API 模式通过已授权的 1688 采购账号读取商品详情。
- 桌面交接只挂在执行操作的按钮或表单提交入口。切换标签、查看模型记录、展开说明及勾选列表在当前网页完成。草稿图片翻译在网页确认后先保存草稿，桌面端按该版本和同一批次编号处理已选图片。仅恢复确认框的交接继续等待用户提交。
- 本机模型设置先经受限 `configureModels` IPC 保存，再向业务 HTTP 提交连接引用；不把命令、代理和资料目录作为后端持久配置。后端共享类型仍通过原生成器产出。
- 本机配置、浏览器资料和临时文件沿用系统应用数据目录 `Champion ERP/backend`；业务数据库与资产迁入统一后端。启动地址、迁移和打包说明见 [桌面与统一后端](../docs/desktop-packaging.md)。

## 验证

单元与组件测试使用 Vitest、jsdom 和 Vue Test Utils，测试就近放置。按改动范围运行测试、类型或构建检查；后端共享 Schema 变化时同步生成并检查前端类型。
